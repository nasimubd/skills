# Operating guide

These rules keep autonomous edits predictable on Asana Personal.

## Rule 01

Use project GIDs from configuration rather than names.

## Rule 02

Resolve the current user before mutating resources.

## Rule 03

Inspect sections before choosing a destination.

## Rule 04

Prefer existing tags over creating near-duplicates.

## Rule 05

Keep LeadScout identifiers in task notes.

## Rule 06

Treat identifiers as idempotency keys.

## Rule 07

Search before creating a handoff task.

## Rule 08

Keep task names concise and searchable.

## Rule 09

Put the latest reply in the task notes.

## Rule 10

Include a source conversation link when available.

## Rule 11

Include a recommended human action.

## Rule 12

Include evidence timestamps in handoffs.

## Rule 13

Use stories for incremental context.

## Rule 14

Do not overwrite useful historical comments.

## Rule 15

Do not store secrets in notes.

## Rule 16

Do not depend on custom fields.

## Rule 17

Do not depend on rules.

## Rule 18

Use sections for workflow state.

## Rule 19

Use tags for lightweight classification.

## Rule 20

Keep the free-plan workflow portable.

## Rule 21

Ask before deletion.

## Rule 22

Ask before mass completion.

## Rule 23

Ask before bulk reassignment.

## Rule 24

Treat a single task edit as routine.

## Rule 25

Report every mutation after execution.

## Rule 26

Report uncertainty instead of inventing facts.

## Rule 27

Retry only safe GET requests automatically.

## Rule 28

Avoid retrying non-idempotent POST requests blindly.

## Rule 29

Surface API rate-limit errors clearly.

## Rule 30

Use HTTPS for every API request.

## Rule 31

Never log authorization headers.

## Rule 32

Keep token lookup in the environment.

## Rule 33

Keep workspace and project scope explicit.

## Rule 34

Prefer polling for the initial free-plan deployment.

## Rule 35

Verify webhook signatures if webhooks are enabled.

## Rule 36

Persist synchronization cursors outside task text.

## Rule 37

Record failed synchronization attempts.

## Rule 38

Avoid duplicate comments on retry.

## Rule 39

Use stable markers for generated stories.

## Rule 40

Fetch current state after webhook events.

## Rule 41

Treat deleted tasks as synchronization events.

## Rule 42

Preserve human edits when updating context.

## Rule 43

Keep handoffs understandable without LeadScout access.

## Rule 44

Keep task descriptions bounded in size.

## Rule 45

Summarize long email histories.

## Rule 46

Link to canonical records rather than copying secrets.

## Rule 47

Validate configuration before any mutation.

## Rule 48
